## 一、这是什么

一个 Android App，帮玩家在手机上把《Casualties Unknown》跑起来，
并管理模组、语言包和存档备份。

**核心价值**：原本要手动折腾半小时的步骤，做成了一键。

## 四、如何构建 / 签名

### ⚠️ 源码树已丢失

`/root/app/`（源码 + `release.jks` + `build.sh`）在 **2026-10-27 容器重置**后整体消失，
`/sdcard` 上没有任何备份。v1.3 是在 v1.2 的 APK 上直接改包得到的：

- `baksmali d classes.dex` → 改 `MainActivity.smali` 里的文案 → `smali a` 回汇编；
- `AndroidManifest.xml` 是二进制 AXML，直接改字符串池 `1.2→1.3` 和 versionCode `2→3`；
- 原 APK 的 `assets/game.zip` 保持 **STORE**（不重压缩）；
- `zipalign` → `apksigner` 重新签名。

### 构建/改包工具（Ubuntu 容器，apt 用清华镜像）

```bash
apt-get install openjdk-17-jre-headless apksigner libsmali-java zipalign
```

### 发布签名（2026-10-29 重建的新密钥）

| 项 | 值 |
|---|---|
| 密钥文件 | `/sdcard/工程/keys/release.jks` |
| alias | `cuinstaller` |
| 库密码 / 密钥密码 | `CuInstaller2026` |
| 算法 | RSA 2048 / SHA384withRSA |
| 有效期 | 2026-10-29 → 2054-03-16 |
| 证书 SHA-256 | `17B785F1260C8B06CEB1E97B1EFE5F9B6C120815BCA6FE24DD4E1E477093A74A` |

⚠️ 这是**新密钥**：原 `release.jks`（SHA-256 `059a760f…544a1`）已随容器重置丢失。
因此旧密钥签名的 v1.2 **无法被 v1.3 覆盖安装**（会报 signatures do not match），需先卸载。

⚠️ **务必把这个 jks 再备份到手机之外**（电脑/网盘）。`/sdcard` 会丢，丢了就永远无法给已装用户发更新。

### 签名命令

```bash
zipalign -f 4 app-unsigned.apk app-aligned.apk
apksigner sign --ks /sdcard/工程/keys/release.jks \
    --ks-key-alias cuinstaller \
    --ks-pass pass:CuInstaller2026 --key-pass pass:CuInstaller2026 \
    --out app-release.apk app-aligned.apk
apksigner verify --print-certs app-release.apk
```

> `targetSdk ≥ 30` 要求 `resources.arsc` 未压缩且 4 字节对齐，所以必须 **先 zipalign 再签名**，
> 否则安装报 `resources.arsc ... not aligned`。

### 主题色/外观是怎么加进去的（smali 级注入）

没有完整源码也能加功能，做法是「新类 + 少量钩子 + 全局常量替换」：

1. `Theme.java`：`accent()/accentDark()` 返回当前强调色（`cu_theme → accent`），`pick(Activity)` 弹 8 色单选框。
2. `Skin.java`：外观总控
   - `attach(Context, LinearLayout)` 在设置页末尾加「外观」卡片；
   - 菜单：主题色 / 选择背景图 / 背景显示（填充·拉伸）/ 玻璃样式（无·毛玻璃·液态玻璃）/ 移除背景；
   - `onResult(...)`：接收相册选图（请求码 9101），降采样 + 模糊后存 `filesDir/skin_bg.jpg`；
   - `apply(Activity)`：把背景铺到 `shell`（`android.R.id.content` 的第一个子 View），
     把页面容器上的 `ColorDrawable` 背景清空让图透出来，再遍历 View 树给卡片上透明度/描边；
   - `applyLater(...)`：页面切换用动画时，延迟 120ms / 520ms 各刷一次。
3. `javac`（android.jar API 30）→ `d8` → `baksmali`，把 `Theme*/Skin*.smali` 放进反汇编目录。
4. `MainActivity.smali` 钩子：
   - `onCreate` 开头 → `Theme.init`；
   - `tabSet()` 末尾 → `Skin.attach`；
   - `onResume` → `Skin.apply`；
   - `onActivityResult` 开头 → `Skin.onResult`；
   - 两个 `setPage` 的每个 `return-void` 前 → `Skin.applyLater`（动画结束再刷一次）。
5. 全局替换强调色常量（所有 smali）：
   - `const x, -0xb52180`（0xFF4ADE80）→ `Theme.accent()`
   - `const x, -0xdd3aa2`（0xFF22C55E）→ `Theme.accentDark()`

   ⚠️ **替换时必须排除 `Theme.smali` 自己**，否则它静态初始化里的默认值也会被换掉，
   结果 `accent()` 返回 0（界面强调色全透明）。这个坑已经踩过一次。
6. `smali a` 回汇编 → 用原 APK 的 res/assets/manifest 重打包 → zipalign → apksigner。

> 当前「液态玻璃」的做法：`paint()` 里把卡片的 `GradientDrawable` 换成三段竖向渐变
> （顶部 `0xD93A4757` → 中部 `0xA60F141A` → 底部 `0xF20A0E13`）再叠 1dp 白色描边；
> 毛玻璃则是平涂 `setAlpha(225)`。没有真正的实时模糊/折射（Android 上要 `RenderEffect`，
> 且只对窗口/对话框生效）。
>
> 踩坑记录：页面的根容器本身带一层不透明 `ColorDrawable`，只设 `shell` 背景会被它盖住——
> 必须把它清掉，背景才看得见。另外 `paint()` 要跳过 `TextView`，否则按钮的强调色背景
> 会被渐变覆盖成透明玻璃。

## 六、关键实现细节

### 存档格式

`save.sv` = **gzip 压缩的 JSON**，解压后约 13 KB。

关键字段：

```
cId        存档 ID（= runId）
cVer       存档版本
cAge       存活天数
cHeight    身高
runTime    游戏时长
biome      生物群系
body       身体部位状态（61 项）
limbs      肢体状态（15 × 18）
items      物品
runSettings 局内设置（41 项）
```

### 存档模组的 slots 目录

`CuSaveManager` 的 `slots` 根目录是 **`Path.Combine(dirname(DLL), "slots")`**
—— 即模组 DLL 旁边的 `slots/`，不是游戏根目录。

所以 `Core.findSlotsDir()` 是**递归查找**的（深度 5）。

### 中文语言包

`<游戏>/CasualtiesUnknown_Data/Lang/zh-CN.json`，按 section 组织：

```
main / buildings / moodles / other / ...
```

物品 ID 在 `main` section 下。

### 零 root 设计

日常功能（装游戏、管模组、备份存档）**完全不需要 root**。

只有两种情况需要：

1. 游戏装在 `/data/` 下（Winlator 的私有目录）→ 用 `nsenter` 提权
2. 某些设备上写入失败

Root 的用法是**静默的** —— 用户看不到"root"字样。

### 尺寸

```

```

### 动效

| 场景 | 实现 |
|---|---|
| 切 Tab | 旧页淡出+缩小0.98（140ms）→ 新页淡入+上移14dp（260ms） |
| 点选项 | 圆点立刻变 → 绿框滑动（320ms，自绘） |
| 按按钮 | scale 0.96（90ms）→ 弹回 1.0（160ms Overshoot） |

### 组件：`HighlightList`

能画「滑动选中框」的 `LinearLayout`。

**核心设计**：不叠加任何 View，列表自己在 `dispatchDraw` 里画框。

```java
@Override
protected void dispatchDraw(Canvas canvas) {
    super.dispatchDraw(canvas);        // 先画卡片
    if (hlHeight > 1f && alpha > 0) {  // 框画在最上层
        canvas.drawRoundRect(rect, radius, radius, paint);
    }
}
```

**为什么不用叠加 View**（三次失败）：

| 做法 | 失败原因 |
|---|---|
| `topMargin/height` 动画 | 每帧触发 measure/layout → 卡顿 |
| `MATCH_PARENT` 高度 | 撑高容器 → 下方按钮被挤走 |
| `0dp` 高度 | **0 高度 View 根本不绘制** → 框消失 |

## 八、踩过的坑（重要）

### 构建相关

**① `write` 工具在这台机器上生成的是符号链接**

`write` 创建的文件是指向临时目录的软链，临时目录被清理后就变成死链。
**用 bash heredoc 写文件。**

**② native 库必须用 `zip -0` 且路径带 `lib/`**

```bash
# ✓ 在项目根目录执行
zip -q -0 -r base.apk lib

# ✗ 在 lib/ 里执行会得到 arm64-v8a/...（少一层）
```

**③ Java 编译时 `round()` 签名容易错**

`Ui.round(int color, float radiusPx)` 是 2 参数，不是 3 参数。

### UI 相关

**④ `setContentView` 导致白屏闪烁**

切页面时旧视图已销毁、新视图未画出 → 露白。
**改成不重建 shell，只换里面的子 View** + 窗口背景设深色。

**⑤ 卡片 `alpha=0` 后被动画卡住**

`Ui.card()` 原来预设 `alpha=0`，靠 stagger 动画恢复。动画一失败 → 卡片永远不可见。
**已彻底去掉 stagger**，只保留整页淡入。

**⑥ `Button` 有两个最小高度**

```java
setMinHeight(0);        // View 的
setMinimumHeight(0);    // TextView 的（Button 继承的）
```

两个都要清，否则设 44dp 会被撑到 48dp。

**⑦ `Ui.cardHeader()` 只能放纵向容器**

它返回的 `LinearLayout` 硬编码了 `MATCH_PARENT` 宽度，
放进**横向**容器会导致标题渲染异常（字糊、被裁）。

### 文案相关

**⑧ 声明文案是混淆存储的**

`Obf.java` 用 Base64 + 循环异或（密钥 `CuMgr2026#obf`）。
改文案必须**先解密、改、再加密**，直接搜字符串找不到。

`Obf.intact()` 校验的是**首尾特征**：
以「本软件完全免费」开头、以「请立即退款并举报。」结尾。
